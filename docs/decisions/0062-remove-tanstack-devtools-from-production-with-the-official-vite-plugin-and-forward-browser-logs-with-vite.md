# ADR-0062: TanStack Devtools は公式の Vite の plugin で本番から外し、event bus と Console Piping を止めて、ブラウザのログは Vite の `server.forwardConsole` で端末へ送る

- Status: Accepted
- Date: 2026-11-07
- 関連: ADR-0018 (Table Devtools への登録)

## Context

dev の画面に TanStack Devtools の panel (`<TanStackDevtools>`) を出す。本番の build には入れない。開発中のブラウザの console の警告とエラーは、開発者とエージェントが読む端末にも出す。

- TanStack Devtools の docs「Vite Plugin」は、`@tanstack/devtools-vite` を dev の依存に入れ、Vite の config の最初の plugin に置くよう案内する。2026-11-03 時点 (`@tanstack/devtools-vite` 0.8.6) の記録では、plugin の sub-plugin のうち、アプリの JSX を触る transform (`inject-source`・`remove-devtools-on-build`・`better-console-logs`・`console-pipe-transform`) は `enforce: 'pre'` で、framework の plugin が JSX を変換する前に動いていた (`src/plugin.ts`)
- docs「Production」は、Vite の project では plugin が本番の build から devtools を外すとする。devtools を import したファイルを環境で分けて読む形は、Vite でない project のための形である
- Void の docs は `voidPlugin()` を framework の plugin より前に置く (`node_modules/void/docs/guide/pages-routing/overview.md` の `plugins: [voidPlugin(), voidReact()]`。"must come before the framework plugin" の注記は `integrations/frameworks/tanstack-start.md`)。devtools の plugin を最初に置いても、この順は崩れない
- Vite docs「Server Options」の `server.forwardConsole` は、dev の間にブラウザの console と未処理の error を Vite の端末へ送る。既定は、AI の coding agent を検出したときだけ `true` になる。`true` と object (`unhandledErrors`・`logLevels`) で送るものは同じ節にある
- 2026-11-03 時点 (Vite+ 1.4.0 が同梱する Vite 8.3.5) の記録では、`resolveForwardConsoleOptions` は、`std-env` の判定で agent を検出し、`AI_AGENT`・`CLAUDECODE`・`CLAUDE_CODE`・`CODEX_THREAD_ID` などの環境変数で agent とみなしていた (vitejs/vite#23744)

### Void の dev で各機能が働くか

2026-11-03 に、`vp dev` (Void 1.4.0、Vite+ 1.4.0 が同梱する Vite 8.3.5、`@cloudflare/vite-plugin` 1.66.0、`@tanstack/devtools-vite` 0.8.6) と `vp build` で確かめた。ページの server 側の描画は workerd で動く。「人の端末」は `AI_AGENT`・`CLAUDECODE`・`CLAUDE_CODE` を外して起動した dev を指す。

| 機能                                               | 働くか                  | 観測                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source Injection (`data-tsd-source` の属性)        | 働く                    | server の HTML と hydration 後の DOM の両方に付き、hydration の警告は出ない。panel の source inspector は `location.origin` の `/__tsd/open-source` を開く (`@tanstack/devtools` 0.15.0 の `source-inspector.tsx`)。dev の port への GET は middleware の引数検査 (400) まで届き、loopback の port への GET は 403 になる。エディタが開くことまでは確かめていない                           |
| 本番からの除去 (`removeDevtoolsOnBuild`)           | 働く                    | `vp build` が client と ssr の build で `Removed devtools code from: /src/components/app-devtools.tsx` を出す。`dist/client/assets` の `.js` の合計は plugin の無い build より増えず (832653 → 832647 byte)、devtools の font も出ない                                                                                                                                                      |
| Enhanced Logs (端末)                               | 働く                    | workerd の `console.log` が端末に `LOG /pages/<page>.tsx:<line>:<column>` を付けて出る                                                                                                                                                                                                                                                                                                      |
| Enhanced Logs (ブラウザの console の Go to Source) | 働かない                | リンクの port が dev server の port でなく、開くと 403 が返る (下の「port の食い違い」)                                                                                                                                                                                                                                                                                                     |
| Console Piping (ブラウザ → 端末)                   | 届く。止める (決定)     | ブラウザの `console.log`・`console.warn` が端末に `[Client]` を付けて出る。注入先は下の「Console Piping の注入先」。agent を検出した端末では `server.forwardConsole` の既定と重なり、`console.warn` が 2 回ずつ出た                                                                                                                                                                         |
| Console Piping (server → ブラウザ)                 | 働かない。止める (決定) | 注入したコードの送り先が loopback の port になる dev では、workerd が `http://localhost:<loopback の port>/__tsd/console-pipe/server` へ送る POST が 403 になる (Local Explorer の observability の span で確かめた)。dev を新しく起動した run では送り先が dev の port で、POST は 200 で届いた (2026-11-03)。どちらでも、注入したコードは送信の失敗を握りつぶすので、失敗の知らせは出ない |
| Vite の `server.forwardConsole` (ブラウザ → 端末)  | 働く (決定の値を明示)   | 人の端末でも agent の端末でも、ブラウザの `console.warn`・`console.error`・`console.log` と未処理の error と rejection が、端末に `[vite+] (client) [console.warn] <message>` などで 1 回ずつ出る (2026-11-07、Void 1.5.0)。`consolePiping.enabled: false` では、ブラウザは `/__tsd/console-pipe` へ要求を送らず、注入先だったファイルにも piping のコードが入らない                        |
| server の event bus、plugin の Marketplace         | 起こさない (決定)       | `eventBusConfig.enabled: false` で、event bus の既定の port 4206 は LISTEN しない                                                                                                                                                                                                                                                                                                           |

port の食い違い: 2026-11-03 時点 (Void 1.4.0、`@tanstack/devtools-vite` 0.8.6、`@cloudflare/vite-plugin` 1.66.0、miniflare 5.20261023.1-beta) の記録では、plugin は、dev server の middleware に来た要求の `req.socket.localPort` で、リンクと送り先の port を上書きしていた (`@tanstack/devtools:custom-server`)。Void の dev の wrangler 設定は `assets.run_worker_first: ["/**"]` で、`/src/*.ts` の要求も先に Worker へ渡っていた。`@cloudflare/vite-plugin` の assets の binding (`ASSETS`) は、その要求を Vite の middleware へ渡す node の binding で、miniflare はこれを loopback の HTTP server が受けた要求のまま呼んでいた。このため transform が見る `req.socket.localPort` は loopback の port になりえた。miniflare の loopback は、内部のヘッダの無い要求に 403 を返していた (`#handleLoopback`)。dev を新しく起動した run では、注入された送り先が dev の port だった (2026-11-03)。loopback の port になる起動の条件は調べていない。

Console Piping の注入先: 2026-11-03 時点 (`@tanstack/devtools-vite` 0.8.6、Void 1.4.0) の記録では、plugin は、`<html`・`hydrateRoot`・`createRoot`・`StartClient` のどれかの文字列を含み、`node_modules` の外にあるファイルに piping のコードを入れていた。Void の client の入口 (`@void/react` の `pages-client`) は `node_modules` の中にあるので入らなかった。2026-11-03 の時点では、コメントにこれらの語を含むアプリのファイルに入っていた。

## Decision

**`@tanstack/devtools-vite` を `vite.config.ts` の最初の plugin に置き、`eventBusConfig.enabled: false` と `consolePiping.enabled: false` を渡す。ブラウザの console は `server.forwardConsole` に `{ unhandledErrors: true, logLevels: ["error", "warn", "log"] }` を渡して端末へ送り、Storybook の dev には `.storybook/main.ts` の `viteFinal` で同じ値を渡す。`<TanStackDevtools>` は環境で分けずに import し、本番からは plugin に外させる。**

- 2026-11-05 時点 (`@tanstack/devtools-vite` 0.8.6、`@tanstack/devtools-bundler-core` 0.1.4) の記録では、event bus のサーバは認証の無い要求を受け、有効な npm パッケージなら何でも、その install scripts も含めて dev server の上で install させていた (TanStack/devtools#464、TanStack/devtools#545)。2026-11-03 時点 (`@tanstack/react-devtools` 0.10.13) の記録では、panel はこのサーバにつながなかった (`<TanStackDevtools>` の `eventBusConfig.connectToServerBus` の既定は false だった) ので、その版では、止めても panel の機能は減らなかった
- Console Piping を止めて失うのは、ブラウザの `console.info`・`console.debug` の端末への転送だけである。server → ブラウザは上の表のとおり働いていなかった
- `server.forwardConsole` は既定のままだと人の端末で働かないので、値を明示する。値は `tooling/server/forward-console.ts` に 1 つだけ置き、`vite.config.ts` と `.storybook/main.ts` が import する
- `logLevels` に `info` と `debug` を入れないのは、ブラウザの console に出る Vite の client の接続と HMR の行 (`[vite] connected.`、`[vite] hot updated: <path>`) が `console.debug`、React DevTools の案内が `console.info` だったからである (2026-11-07、Vite+ 1.4.0 が同梱する Vite 8.3.5)。`log` だけを足した値では、部品のファイルを 2 回書き換えても、ブラウザから送った `[console.*]` の行は端末に足されなかった (2026-11-07)
- 2026-11-07 時点 (`@storybook/builder-vite` 10.6.5) の記録では、Storybook の dev に `vite.config.ts` の `forwardConsole` は届かなかった。builder は `vite.config.ts` の設定を読むが、`server` を自分の値で丸ごと差し替えていた (`dist/index.js` の `createViteServer`)。Storybook docs「Vite」は、builder の設定を変える口に `viteFinal` と `mergeConfig` を案内する。2026-11-03 に Storybook の dev で story を開き、ブラウザで `console.warn`・`console.error` を出して端末の行を数えた。`viteFinal` が無いと人の端末に 0 行で、渡すと人の端末でも agent の端末でも `Vite [console.warn] <message>` と `Vite [console.error] <message>` が 1 行ずつ出た。2026-11-07 に決定の値を渡すと、人の端末で `Vite [console.log] <message>` と未処理の error と rejection も 1 行ずつ出た
- 2026-11-03 時点 (`@storybook/addon-vitest` 10.6.4) の記録では、addon も `viteFinal` の結果を story のテストの config に重ねていた (`dist/vitest-plugin/index.js`)。そのまま渡すと、story のテストの出力で、Vitest が出す console の行に `[vite] (client) [console.warn] <message>` の行が重なった (2026-11-03)。`process.env.VITEST` が `"true"` のときは渡さない
- 2026-11-03 時点 (`@tanstack/devtools-bundler-core` 0.1.4) の記録では、plugin が外すのは、devtools の本体のパッケージ (`@tanstack/react-devtools` など 7 つ) を import したファイルの、その import と `<TanStackDevtools>` の JSX と、`plugins` の `render` だけから参照される import だった (`remove-devtools.ts`)。`plugins` に関数の呼び出し (`tableDevtoolsPlugin()`) で渡した import は外していなかったが、JSX が外れると参照が無くなり、build が bundle から落とした (上の表の除去の行)
- `DataTable` が Table Devtools に table を登録する hook (`useTanStackTableDevtools`) は、同じ記録では plugin が外す対象に入っていなかった。dev だけ `import()` で読む形を残す (`src/components/parts/data-table.tsx`)

### 検討した選択肢

| 案                                                                                                                                                    | 評価                                                                                                                                                                                                                                                                                                                                                                                                                | 採否     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| plugin を最初に置き、event bus と Console Piping を止め、ブラウザ → 端末を `server.forwardConsole` (`error`・`warn`・`log` と未処理の error) に任せる | ブラウザ → 端末が、Vite の公式の口で人の端末でも agent の端末でも 1 回ずつ出る。コメントの語に頼る注入が無くなり、workerd も POST を送らない。Source Injection と端末の Enhanced Logs は残る。アプリの `console.log` の行には、Enhanced Logs の開けないリンクが前置きされる                                                                                                                                         | **採用** |
| plugin を最初に置き、event bus だけを止める (Console Piping は有効のまま)                                                                             | docs「Vite Plugin」の既定のまま。人の端末では、ブラウザ → 端末は注入だけが支え、注入先のファイルのコメントから語が消えると黙って止まる。agent の端末では `server.forwardConsole` と重なり、同じ警告が 2 回出る。server → ブラウザは働かないまま、workerd がその都度 POST を送る (送り先が loopback の port なら 403)                                                                                                | 却下     |
| 採用案で、`logLevels` に `info` と `debug` も入れる                                                                                                   | Console Piping と同じ範囲を送れる。`logLevels` は送る `console.*` を level で選ぶだけで、出どころでは絞れない。Vite の client が自分で出す `console.debug` (`[vite] connected.`、`[vite] hot updated: <path>`) と、React の `console.info` (React DevTools の案内) も端末に届き、HMR のたびに server の `hmr update <path>` の行に同じ更新の行が 1 行足される (2026-11-03 に `log`・`info`・`debug` を足して測った) | 却下     |
| 採用案で、`server.forwardConsole: true` (未処理の error と `error`・`warn`) にする                                                                    | ブラウザの `console.log` が、人の端末でも agent の端末でも端末に出ない。アプリの `console.log` の行に開けないリンクが付かない                                                                                                                                                                                                                                                                                       | 却下     |
| plugin を入れず、`<TanStackDevtools>` を dev だけ `import()` で読む                                                                                   | docs「Production」が Vite でない project に案内する形。Vite の project で公式の形から外れ、Source Injection と Enhanced Logs を失う                                                                                                                                                                                                                                                                                 | 却下     |
| 採用案に加えて、Void の dev で働かない Enhanced Logs も切る (`enhancedLogs.enabled: false`)                                                           | ブラウザの console と、端末へ送った `console.log`・`console.error` の行に、開けないリンクが付かなくなる。代わりに、働いている端末の Enhanced Logs (workerd の `console.log` の場所) も失う。2026-11-03 時点 (`@tanstack/devtools-vite` 0.8.6) の記録では、ブラウザと端末を別々に切る option は無かった                                                                                                              | 却下     |

## Consequences

- `<TanStackDevtools>` は JSX のまま、devtools の本体のパッケージを import したファイルに書く。変数に入れたり、別の部品で包んで `lazy` で読んだりすると、2026-11-03 時点 (`@tanstack/devtools-bundler-core` 0.1.4) の記録では、plugin がその JSX を見つけられず本番に残る作りだった
- 2026-11-03 の記録では、ブラウザの console の Enhanced Logs のリンクは開けなかった。panel の source inspector (既定の hotkey は Shift+Alt+Ctrl/Meta) は、dev の port の middleware に要求を送っていた (`@tanstack/devtools` 0.15.0)。エディタが開くかは確かめていない
- 2026-11-07 の記録では、アプリのコードの `console.log` と `console.error` を端末へ送った行には、Enhanced Logs がブラウザ向けに足した前置き (`LOG Go to Source: http://localhost:<loopback の port>/__tsd/open-source?source=<path>:<line>:<column>`) が付いた。リンクは開けなかったが、path と行は読めた。`console.warn` には前置きが付かなかった (2026-11-03 時点の `@tanstack/devtools-bundler-core` 0.1.4 の `enhance-logs.ts` は、`console.log` と `console.error` だけを書き換えていた)
- ブラウザの `console.info`・`console.debug` は端末に出ない。端末で読みたくなったら、`tooling/server/forward-console.ts` の `logLevels` に足す
- server の console の出力は端末に出るが、ブラウザの console には出ない
- `vp build` の出力を `tanstack-devtools` で grep すると、`@tanstack/react-form` が引く `@tanstack/devtools-event-client` のコードが当たる。この plugin の除去の対象ではなく、2026-11-03 には plugin を足す前の build にも同じ chunk があった
